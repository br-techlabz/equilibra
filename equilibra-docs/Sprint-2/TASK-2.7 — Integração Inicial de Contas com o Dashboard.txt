# 8. PATRIMÔNIO LÍQUIDO

Este é o único KPI que pode começar a utilizar dados reais nesta Sprint.

Enquanto não existem transações:

Patrimônio líquido inicial =
soma dos initialBalance das contas de ativo ATIVAS.

Exemplo conceitual:

Conta corrente: R$ 1.500,00
Carteira:        R$   200,00
Investimentos:   R$ 3.000,00

Patrimônio líquido inicial:

R$ 4.700,00

---

# 9. IMPORTANTE — SEMÂNTICA

Não trate esse valor como cálculo definitivo de patrimônio líquido do
sistema.

É uma aproximação válida para o estado atual:

"patrimônio baseado nos saldos iniciais cadastrados".

Quando transações forem implementadas, a fórmula deverá evoluir.

---

# 10. CONTA INATIVA

Contas inativas NÃO devem participar do valor exibido como patrimônio
atual/inicial do Dashboard.

Utilize somente contas ativas.

---

# 11. SALDOS NEGATIVOS

Saldo inicial negativo participa normalmente da soma.

Exemplo:

Conta A: R$ 1.000,00
Conta B: -R$ 300,00

Patrimônio:

R$ 700,00

Não use Math.abs.

---

# 12. PRECISÃO MONETÁRIA

IMPORTANTE:

Não introduza cálculo financeiro ingênuo com Number se isso puder causar
problemas de precisão.

Avalie como os valores monetários chegam da API e como o frontend atual
os representa.

Para uma simples soma de valores DECIMAL(19,2), utilize estratégia segura.

Possibilidade recomendada:

converter cada valor para centavos inteiros de maneira controlada,
somar em centavos e formatar o resultado.

Não adicione biblioteca decimal pesada sem necessidade.

Documente a estratégia.

---

# 13. EXEMPLOS DE TESTE

0,00 + 0,00
= 0,00

100,10 + 200,20
= 300,30

1000,00 + (-350,50)
= 649,50

0,10 + 0,20
= 0,30

O último caso é importante para evitar problemas clássicos de floating
point.
