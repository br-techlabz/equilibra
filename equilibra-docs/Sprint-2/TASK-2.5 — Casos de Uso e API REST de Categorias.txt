# 36. FILTRO BOTH

Não é necessário utilizar:

applicability=BOTH

como filtro público nesta versão se não houver caso de uso real.

Avalie a API.

Preferência:

o filtro representa o CONTEXTO DE USO, não igualdade literal do enum.

Portanto:

EXPENSE
→ EXPENSE + BOTH

INCOME
→ INCOME + BOTH

Documente claramente.

---

# 37. NOMENCLATURA ALTERNATIVA

Se "applicability" como query param tornar a semântica ambígua, você pode
usar algo mais explícito, por exemplo:

usage=EXPENSE
usage=INCOME

Porém, priorize consistência e simplicidade.

Não crie dois filtros equivalentes.

---

# 38. INCLUDE INACTIVE + FILTRO

Cuidado com a semântica.

Os futuros formulários de transações precisarão somente de categorias
ATIVAS.

Para evitar uma API ambígua, defina claramente o comportamento quando:

includeInactive=true
+
applicability=EXPENSE

Preferência:

retornar categorias EXPENSE/BOTH independentemente de active quando
includeInactive=true.

Documente e teste.
