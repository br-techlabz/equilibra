# TASK-6.6 — BACKEND DE METAS FINANCEIRAS

PROJETO: EQUILIBRA
SPRINT: 6 — PLANEJAMENTO FINANCEIRO
STACK: Spring Boot 4 + MySQL + Angular 19

CONTEXTO

Sprint 5 aprovada.
TASK-6.0 — Arquitetura do Planejamento Financeiro concluída.
TASK-6.1 — Backend de Orçamentos concluído.
TASK-6.2 — Interface de Orçamentos concluída.
TASK-6.3 — Backend de Planejado versus Realizado concluído.
TASK-6.4 — Dashboard de Orçamentos concluído.
TASK-6.5 — Alertas de Limites concluídos.

OBJETIVO

Implementar exclusivamente o backend de Metas Financeiras
do Equilibra, conforme decisões aprovadas no ADR
da TASK-6.0.

Permitir ao usuário:

- criar metas financeiras;
- consultar suas metas;
- visualizar detalhes;
- editar informações permitidas;
- concluir/cancelar/arquivar metas, conforme ADR;
- acompanhar progresso, SOMENTE conforme modelo
  expressamente aprovado;
- consultar metas históricas.

Não implementar frontend nesta TASK.

REGRA FUNDAMENTAL

Meta financeira não é transação financeira.

Criar, editar ou concluir uma meta não deve,
por si só, alterar saldos, receitas, despesas,
transferências ou patrimônio líquido.

O ADR da TASK-6.0 prevalece sobre todos
os exemplos deste prompt.

8. VALOR OBJETIVO
==================================================

Usar BigDecimal.

DECIMAL(19,2), se aprovado.

Validar:

- obrigatório;
- maior que zero, salvo ADR diferente;
- máximo permitido;
- até duas casas decimais;
- formato válido.

Rejeitar precisão inválida sem
arredondamento silencioso.

==================================================

- data atual;
- data futura;
- edição da data;
- ausência de data.

Não inventar obrigatoriedade.

16. NÃO CRIAR DINHEIRO FICTÍCIO
==================================================

Criar meta não pode:

- aumentar saldo de conta;
- criar receita;
- criar movimento de ledger;
- alterar patrimônio;
- criar transferência;
- alterar dashboard financeiro.

Uma contribuição virtual, se permitida,
não pode ser tratada como depósito bancário.

==================================================
17. PROGRESSO E PERCENTUAL
==================================================

Se previsto no ADR:

progressAmount = valor de progresso aprovado.

remainingAmount = targetAmount - progressAmount.

progressPercentage =
(progressAmount / targetAmount) * 100.

Usar BigDecimal.

Não usar float/double.

Definir arredondamento e limites
conforme ADR.

Não persistir valores derivados sem justificativa.
