# 3. Estratégia de logout

A arquitetura atual utiliza:

- access token JWT
- stateless backend
- token somente em memória
- sem refresh token
- sem blacklist

Portanto, logout nesta versão é uma operação CLIENT-SIDE.

Logout deverá:

1. apagar access token da memória;
2. apagar currentUser;
3. alterar estado para unauthenticated;
4. navegar para `/login`.

---

# 4. Não criar endpoint de logout

NÃO crie:

`POST /api/auth/logout`

apenas por convenção.

Sem:

- sessão server-side
- refresh token
- blacklist

o backend não possui estado útil para invalidar.

Documente essa decisão.

---

# 5. Validade do JWT após logout

Documente claramente:

O JWT emitido continua criptograficamente válido até `exp`.

O logout remove a capacidade normal do frontend de continuar utilizando esse token porque ele deixa de existir na memória.

Esse é um trade-off conhecido da estratégia stateless atual.

Não implemente blacklist apenas para alterar esse comportamento.
