# TASK-3.4 — Casos de Uso e API REST de Receitas

O objetivo é implementar a API completa de Receitas/Rendas utilizando o
mesmo ledger financeiro definido na TASK-3.0 e implementado na TASK-3.1.

O usuário autenticado deverá conseguir:

- registrar uma receita;
- listar receitas;
- consultar uma receita;
- editar uma receita;
- cancelar uma receita.

A implementação deve aproveitar padrões consolidados pela API de Despesas,
mas NÃO deve simplesmente duplicar código sem análise.

NÃO implementar nesta TASK:

- frontend de Receitas;
- Transferências;
- Tags;
- Attachments;
- Dashboard financeiro real;
- relatórios;
- saldo persistido;
- DELETE físico;
- API genérica de Transactions;
- abstrações genéricas prematuras.

# 3. PRINCÍPIO FINANCEIRO

Income representa entrada de dinheiro em uma AssetAccount.

Conceitualmente:

accountBalance += amount

Mas:

NÃO atualizar saldo persistido.

O efeito será derivado posteriormente do ledger.

# 4. AMOUNT

Assim como Expense:

amount é sempre magnitude positiva.

Exemplo:

Receita de R$ 1.500,00

amount:

1500.00

NÃO:

+1500.00 como mecanismo para identificar o tipo.

O tipo determina o efeito.
