# TASK-3.8 — Saldo Corrente e Patrimônio Derivados do Ledger

Objetivo:

Transformar o ledger financeiro na fonte real para cálculo de:

1. saldo corrente de cada AssetAccount;
2. patrimônio líquido atual do usuário.

IMPORTANTE:

NÃO persistir currentBalance.

O saldo corrente deve ser DERIVADO.

A fórmula conceitual é:

currentBalance(account)
=
initialBalance
+ receitas ativas da conta
- despesas ativas da conta
+ transferências ativas recebidas
- transferências ativas enviadas

O patrimônio líquido atual é:

netWorth
=
Σ currentBalance(contas consideradas)

A implementação REAL deve respeitar o ADR da TASK-3.0 e a estrutura
implementada nas TASKs 3.1–3.7.

# 16. FÓRMULA GERAL

Para uma conta A:

currentBalance(A)
=
initialBalance(A)
+ activeIncome(A)
- activeExpense(A)
+ activeIncomingTransfers(A)
- activeOutgoingTransfers(A)

Se o ledger usa AccountMovement, adapte:

currentBalance(A)
=
initialBalance(A)
+
SUM(active financial movements affecting A)

Preferir a fórmula natural ao modelo real.

# 156. DEFINITION OF DONE

TASK-3.8 estará concluída quando:

- currentBalance for derivado do ledger;
- currentBalance NÃO for persistido;
- initialBalance continuar sendo base;
- Expense ACTIVE diminuir saldo;
- Income ACTIVE aumentar saldo;
- Transfer ACTIVE debitar source;
- Transfer ACTIVE creditar destination;
- CANCELLED não afetar saldo;
- Transfer preservar netWorth;
- Expense reduzir netWorth;
- Income aumentar netWorth;
- cancelamentos recalcularem corretamente;
- edições recalcularem corretamente;
- saldo negativo funcionar;
- precisão decimal estiver correta;
- ownership estiver protegido;
- balance IDOR retornar 404;
- netWorth for owner-scoped;
- política de contas inativas estiver documentada;
- agregação não possuir N+1;
- banco fizer agregação quando apropriado;
- MySQL/Testcontainers validar queries;
- response de conta puder expor currentBalance derivado;
- requests não aceitarem currentBalance;
- UI de Accounts mostrar saldo atual;
- formulário continuar editando somente saldo inicial conforme política;
- política de edição de initialBalance após transações for resolvida ou
  explicitamente documentada;
- Dashboard deixar de usar initialBalance para patrimônio, se integração
  mínima for segura;
- filtro de período não alterar patrimônio atual;
- OpenAPI estiver atualizado;
- regressões passarem;
- builds passarem.
