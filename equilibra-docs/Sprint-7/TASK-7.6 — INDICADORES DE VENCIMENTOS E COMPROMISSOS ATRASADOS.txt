OBJETIVO

Implementar indicadores de vencimentos
e compromissos atrasados, reutilizando
as entidades e endpoints existentes.

Permitir identificar:

- compromissos atrasados;
- compromissos que vencem hoje;
- compromissos próximos do vencimento;
- compromissos pendentes futuros;
- compromissos efetivados, quando aplicável;
- valores financeiros correspondentes.

Implementar cálculo autoritativo no backend
e apresentação integrada no frontend
conforme escopo autorizado pelo ADR.

Não implementar notificações externas.

Não modificar o ledger.

4. PRINCÍPIO CENTRAL
==================================================

Indicadores são derivados de
compromissos financeiros existentes.

Não criar movimentos no ledger.

Não modificar saldos reais.

Não criar nova fonte de verdade.

==================================================
5. DATA DE REFERÊNCIA
==================================================

Usar data civil conforme ADR.

Definir timezone explicitamente.

Não depender silenciosamente
do timezone do servidor.

Testar mudança de dia.

==================================================
6. ATRASADO
==================================================

Classificar como atrasado somente
compromisso elegível cuja data
de vencimento seja anterior
à data de referência.

Respeitar estados aprovados.

Não classificar efetivado
como atrasado pendente.

==================================================
7. VENCE HOJE
==================================================

dueDate igual à data de referência.

Estado elegível.

Não incluir cancelados ou efetivados
indevidamente.

==================================================
8. PRÓXIMO DO VENCIMENTO
==================================================

Usar janela aprovada no ADR.

Exemplo conceitual:
próximos 7 dias.

Não adotar 7 dias sem confirmação.

Definir limites inclusivos/exclusivos.

==================================================
9. PENDENTE FUTURO
==================================================

Compromisso elegível com vencimento
posterior à janela de proximidade.

Evitar sobreposição com outras classes.

==================================================
10. EFETIVADOS
==================================================

Se indicador existir:

usar estado real do compromisso.

Não confundir valor efetivado
com valor previsto.

==================================================
11. CANCELADOS
==================================================

Não incluir cancelados em valores
pendentes ou atrasados.

Se houver métrica histórica,
apresentar separadamente.

==================================================
12. RECEITAS
==================================================

Diferenciar valores a receber
de valores a pagar.

Não somar receitas e despesas
como uma obrigação única.

==================================================
13. DESPESAS
==================================================

Calcular:

quantidade;
valor total previsto;
eventuais saldos pendentes aprovados.

Usar BigDecimal.

==================================================
14. PAGAMENTOS PARCIAIS
==================================================

Se aprovados:

calcular saldo ainda devido.

Não contar valor já efetivado
como pendente.

Se não suportados:
NOT APPLICABLE.

==================================================
15. CLASSIFICAÇÃO EXCLUSIVA
==================================================

Um compromisso não deve aparecer
simultaneamente como:

atrasado;
vence hoje;
próximo;
futuro;

salvo regra explícita de
categorias sobrepostas.

==================================================
16. FÓRMULAS
==================================================

Para cada grupo:

count = quantidade de compromissos elegíveis.

amount = soma de valores pendentes
conforme modelo aprovado.

Usar BigDecimal.

Não usar float/double.

==================================================
17. FILTRO POR CONTA
==================================================

Todas owner-scoped.

Não incluir dados de conta estrangeira.

==================================================
