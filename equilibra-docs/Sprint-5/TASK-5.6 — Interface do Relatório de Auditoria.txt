# TASK-5.6 — Interface do Relatório de Auditoria

PROJETO: Equilibra
SPRINT: 5 — Relatórios Financeiros
STACK: Angular 19, Spring Boot 4, MySQL

CONTEXTO
TASK-5.0 — ADR de relatórios concluído.
TASK-5.1 — Backend do Relatório Financeiro concluído.
TASK-5.2 — Verificar status real no repositório.

TASK-5.4 — Interface do Relatório por Categoria concluída.
TASK-5.5 — Backend do Relatório de Auditoria concluído.

OBJETIVO
Implementar exclusivamente a interface Angular do Relatório de Auditoria,
consumindo o endpoint real da TASK-5.5.

Permitir ao usuário:
- consultar transações lógicas;
- filtrar por período;
- filtrar por uma, várias ou todas as contas;
- filtrar por tipo e status;
- utilizar outros filtros aprovados no ADR/API;
- consultar lançamentos cancelados;
- visualizar dados de rastreabilidade existentes;
- navegar entre páginas;
- consultar detalhes de uma transação sem alterar dados.

NÃO implementar exportações nesta TASK.

6. FILTROS
==================================================

Implementar somente filtros suportados pelo backend.

Obrigatórios conforme ADR:

- período;
- uma, várias ou todas as contas;
- tipo;
- status.

Adicionais somente se API suportar:

- categorias;
- tags;
- ordenação customizada.

Não inventar parâmetros.

==================================================
7. PERÍODO
==================================================

Usar semântica temporal aprovada no ADR.

O filtro financeiro utiliza occurredAt.

Se a interface trabalha com datas inclusivas,
converter corretamente para os limites reais da API.

Evitar deslocamentos por timezone.

Reutilizar helpers existentes.

==================================================
8. FILTRO DE CONTAS
==================================================

Permitir:

Todas as contas;
Uma conta;
Várias contas.

Usar nomes das contas.

Incluir contas inativas históricas conforme ADR.

Não enviar ownerId.

Ausência de accountIds deve seguir contrato da API.

==================================================
9. FILTRO DE TIPO
==================================================

Opções conforme enums reais:

Todos
Receitas
Despesas
Transferências

Não enviar strings incompatíveis com o backend.

==================================================
10. FILTRO DE STATUS
==================================================

Opções conforme contrato real:

Todos
Ativos
Cancelados

O padrão deve ser exatamente o definido na TASK-5.5.

Se backend definiu ALL por padrão:

selecionar "Todos" inicialmente.

Não ocultar cancelados por conveniência.

==================================================
11. FILTROS ADICIONAIS
==================================================

Se categorias forem suportadas:

- permitir categorias próprias;
- preservar categorias inativas históricas;
- seguir formato real do filtro.

Se tags forem suportadas:

- permitir seleção múltipla;
- usar semântica ANY/ALL aprovada;
- incluir tags inativas históricas quando previsto.

Não criar filtragem financeira client-side.

==================================================
12. DRAFT VS APPLIED
==================================================

Separar:

draftFilters
appliedFilters

Editar filtros não deve fazer os dados exibidos
parecerem pertencer ao novo filtro antes da aplicação.

Botões:

Aplicar filtros
Restaurar filtros

Ao aplicar filtros:

resetar página para a primeira.

13. ESTADO NA URL

Não colocar JWT, ownerId ou informações sensíveis na URL.

==================================================
21. TAGS
==================================================

Se DTO inclui tags:

==================================================
22. ANEXOS

Downloads devem continuar autenticados via HttpClient Blob.

Nunca usar JWT em query string.

32. ERROS

500:

Reutilizar Problem Details e Request ID.
