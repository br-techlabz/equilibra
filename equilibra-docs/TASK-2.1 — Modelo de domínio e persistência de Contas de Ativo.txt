# 2. Conceito de Conta de Ativo

Uma Conta de Ativo representa um local onde o usuário possui recursos financeiros.

Exemplos:

- conta corrente;
- conta poupança;
- carteira de dinheiro;
- conta digital;
- investimento;
- outros ativos financeiros.

Ela NÃO representa uma despesa.

Ela NÃO representa uma transação.

---

# 3. Terminologia

No domínio/backend utilize um nome consistente.

Preferência:

`AssetAccount`

Evite misturar:

- Account;
- BankAccount;
- Wallet;
- Asset;
- ContaAtivo;

para representar o mesmo agregado.

Se a arquitetura atual possuir convenção melhor, explique antes de divergir.

# 6. Ownership

Toda conta pertence a exatamente um usuário.

Conceitualmente:

`AssetAccount.ownerId`

`User.id`

# 7. Regra crítica de segurança

O owner NUNCA deverá ser definido por dados enviados pelo frontend.

Regra permanente:

`ownerId = CurrentUser.id()`

e nunca:

`ownerId = request.ownerId`

Embora a API REST ainda não seja criada nesta TASK, modele domínio e persistência para suportar essa regra.

# 12. Saldo inicial

Campo:

`initialBalance`

Exemplo:

Usuário possui R$ 1.250,35 na conta ao começar a utilizar o sistema.

Então:

`initialBalance = 1250.35`

# 22. Desativação

Conta desativada:

- continua existindo;
- mantém histórico;
- poderá continuar sendo referenciada por transações históricas;
- não deverá ser oferecida futuramente para novos lançamentos, salvo regra específica.

# 23. Não usar exclusão física como regra principal

Como contas poderão possuir histórico financeiro, a estratégia funcional futura deverá favorecer:

**desativação**

em vez de exclusão física.

Nesta TASK, prepare o modelo para isso.

# 28. Contas inativas e nomes

`Nubank`

**SIM.**

Analise cuidadosamente como representar isso no MySQL.
